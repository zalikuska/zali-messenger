# Голосовые звонки (WebRTC full mesh) — инварианты

Вся WebRTC-логика живёт в `web/src/interface/voice_*.js` (`voice_transport`,
`voice_media`, `voice_negotiation`, `voice_call`, `voice_signal`, `voice_ui`) и
исполняется в WebView; нативные шеллы (macOS/Windows/iOS/Android) только
ретранслируют `voice_*` по WS. **Правки голоса дублировать в нативные клиенты
не нужно** — достаточно `bundle_web.py`.

Скилл разбит на три файла — читай нужный целиком, не выдёргивая пункты (инварианты
взаимосвязаны). Подсказка по пути файла приходит хуком.

| Что правишь | Файл |
|---|---|
| Согласование: offer/answer, polite peer, ICE, `voice_signal.js`, `voice_negotiation.js` | этот файл (ниже) |
| Комнаты и жизненный цикл: presence, устройства, инвайты, `voice_transport.js`, `server/src/voice.rs` | `.claude/skills/voice-calls/room-lifecycle.md` |
| Битрейт, телеметрия звука, WS keepalive/heartbeat, `voice_media.js`, `server/src/realtime.rs` | `.claude/skills/voice-calls/media-and-ws.md` |

## Согласование (offer/answer/ICE)

- **`isPoliteVoicePeer` обязана быть строгой инверсией
  `shouldInitiateVoiceOffer`.** Обе раньше возвращали одинаковое
  `me.localeCompare(other) < 0`, из-за чего владелец оффера оказывался
  «вежливым». При встречных офферах это давало звонок, в котором **никто не
  отправлял `answer`**: невежливая сторона штатно отбрасывала входящий оффер,
  а вежливая откатывала свой — тот, ответа на который ждал собеседник. ICE
  при этом продолжает ходить, звонок выглядит подключённым и молчит.
  Диагностика: `grep 'VOICE.*ROUTE' | grep -oE 'signalType=[a-z]+' | sort | uniq -c`
  — если `answer` равен нулю, это оно.
- **`voice.inviter` — «кто позвонил», пишется только из инвайта, принятия и
  `voice_room_state` (поле `initiator`) — никогда из входящего оффера.**
  Отправитель оффера — тот, кто пересогласует (камера, ICE-restart). Лестница
  владельца оффера падает на `inviter`, когда `callTrack` нет (у клиента,
  восстановленного из снапшота комнаты после перезагрузки посреди звонка): до
  2026-09-10 такой клиент решал по порядку имён, собеседник — по
  `callTrack.direction`, и для пар, где вызываемый сортируется раньше
  звонящего, оба владели оффером или никто. Проверяется `voice_doctor`.
- Откат оффера (`setLocalDescription({type:'rollback'})`) допустим только из
  `have-local-offer`. Из любого другого состояния он бросает исключение,
  обрывающее обработчик — ответ не создаётся.
- `handleVoiceSignal` применяет сигналы через цепочку промисов на каждого
  пира. Без неё обработчики переплетались на `await`, и ICE-кандидат мог
  попасть в `pendingIceCandidates` уже после слива очереди — такая пара
  никогда не завершала ICE.
- `ensureVoiceLocalStream()` дедуплицирует одновременные `getUserMedia` через
  общий in-flight промис. Без этого при 3+ участниках каждый входящий оффер
  запускал свой захват, лишние падали с `NotReadableError`.
- `sendVoiceOffer` и ветка ответа на оффер берут защёлку `entry.negotiating`
  **синхронно**, до первого `await`.
- Оффер, пришедший на пира с `connectionState === 'failed'`, **пересоздаёт**
  соединение: у вернувшегося участника DTLS-транспорт уже мёртв.
- ICE-restart разнесён по времени: сторона, не владеющая оффером, ждёт на 5 с
  дольше, иначе оба конца бьют restart одновременно по сломанному линку.
- **Ничего не согласовывается, пока звонок не принят.** `applyVoiceSignal`
  отклоняет любой сигнал при `voice.status === 'incoming'` — иначе звонящий с
  модифицированным клиентом слышал бы собеседника до ответа.
