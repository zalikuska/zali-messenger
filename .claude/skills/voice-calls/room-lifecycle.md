# Голосовые звонки: комнаты и жизненный цикл

Часть скилла `voice-calls` (основной файл — `.claude/skills/voice-calls/SKILL.md`).

- **Звонок принадлежит одному УСТРОЙСТВУ, а не аккаунту (с 0.2b37).** Каждое
  голосовое событие клиента несёт `device` (`voiceDeviceId()`, защёлкнут на
  жизнь страницы), сервер хранит в `VoiceRoom.devices`, каким устройством
  аккаунт сидит в комнате, и адресует события полем `targetDevice`; клиент
  молча пропускает чужие (`handleVoiceEventForOtherDevice`). `voice_leave`,
  keepalive и `voice_signal` от другого устройства того же аккаунта сервер
  игнорирует; явный join/accept с другого устройства забирает звонок, старому
  уходит `voice_error{code:"session_moved"}` (клиент выходит без
  `voice_leave` и без записи в историю). Прод 2026-09-10: аккаунт был
  залогинен на двух Mac, простаивающий слал `voice_leave` через 3 с после
  ответа на первом.
- **Голосовой канал — не «занят».** Личный инвайт тому, кто сидит в голосовом
  канале, звонит поверх канала (`incomingInvite.overChannel`,
  `renderVoiceIncomingStrip`), а не авто-отклоняется: roomId/status/callTrack
  остаются канальными. «Принять» сначала выходит из канала (`voice_leave`),
  потом шлёт `voice_call_accept`; «Отклонить», отмена звонящим, пропуск и
  ответ на другом устройстве снимают только звонок
  (`dismissInviteOverChannel`), канал не трогают; выход из канала другим путём
  превращает инвайт в обычный входящий (`resetVoiceState` →
  `ringInviteAsIncomingCall`). Авто-отказ «занят» остаётся только для идущего
  личного звонка. Прод 2026-09-15: личный звонок между двумя людьми в одном
  канале умирал через 60–100 мс. Проверяется `voice_doctor`.
- **Сервер ставит `vid` каждому своему voice-событию**
  (`send_json_to_user`), одинаковый для всех сокетов пользователя. Нативные
  шеллы отдают `voice_*` и с голосового, и с основного сокета; без `vid`
  серверные события применялись по разу на сокет — одно приглашение получало
  12 отказов «занято».
- **Keepalive восстанавливает забытую сервером комнату, но не завершённую.**
  Явный `voice_leave`/`voice_call_end`, reject, cancel и missed пишут
  надгробие в `AppState.ended_voice_rooms` (DM — комната, канал — пара
  комната+пользователь, 30 мин). Рестарт сервера надгробий не знает, звонки
  переживают деплой.
- **Presence keepalive:** клиент раз в 8 с переотправляет `voice_join` с
  `keepalive: true` (`sendVoiceRoomPresence`), пока в комнате, и сразу при
  восстановлении соединения. Сервер выселяет через **150 с** после закрытия
  WS (`realtime.rs` — сверять именно это число там), клиент сам никогда не
  перезаходит: браузерный `onopen` этого не делает, нативный голосовой WS
  переподключается внутри Swift/Rust.
- **Нативные шеллы сообщают о состоянии транспорта** событием
  `voice_transport_state` (`up`/`down`). До 2026-09-06 JS не знал о
  реконнекте и ждал очередного тика keepalive (до 8 с «призраком»). На `up`
  клиент немедленно переотправляет presence и передёргивает согласование.
- **`voice_send_failed`**: на нативе `sendVoiceEvent` — fire-and-forget,
  всегда «доставлено». Шелл сообщает о payload'ах, которые гарантированно не
  доставит (переполнение очереди — 64 payload'а у обоих шеллов), клиент
  снимает защёлку `offerSent`.
- Флаг `keepalive: true` делает `join_voice_room` недеструктивным —
  `user_voice_rooms` (`DashMap<username, room_id>`) — одна комната на
  аккаунт; без флага два устройства одного аккаунта выбивали бы друг друга
  каждые 8 с.
- `join_voice_room` рассылает состояние комнаты только если состав реально
  изменился; идемпотентный перезаход шлёт снапшот только отправителю.
- **DM-комнату восстанавливает keepalive** (`restore_dm_room`) — `voice_rooms`
  живёт только в памяти, DM-комнату создаёт только `voice_call_invite`, после
  рестарта сервера сигналинг терялся навсегда. Восстановление под теми же
  проверками, что инвайт: id `voice:dm:a:b:stamp` должен называть
  отправителя, оба должны быть в контактах. В восстановленную комнату
  кладётся только отправитель — второй мог реально положить трубку.
- **Каждый `voice_error` несёт машиночитаемый `code`** (`room_not_found`,
  `room_forbidden`, `channel_forbidden`, `not_a_contact`, …) — клиент
  завершает звонок по `room_not_found`, сопоставлять по русскому `message` нельзя.
- **Звонок обязан уметь закончиться сам.** `superviseVoiceLinks` даёт линку
  ~8 минут; когда бюджет исчерпан у всех пиров,
  `concludeDeadVoiceCallIfNeeded` завершает звонок и пишет запись в историю.
  Второй путь — `concludeVanishedVoiceRoom` по `voice_error{code:room_not_found}`.
- **Сетка звонка: 16 плиток 16:9, остальные — кружочками.** Порядок —
  `rankVoiceParticipants` (`voice_ui.js`): демонстрации экрана, затем камеры,
  затем время в комнате; говорящий в ключ **не входит** (сетка прыгала бы на
  каждой паузе, кольцо речи и так есть). Время входа ставит **сервер**
  (`VoiceRoom.joined_at`, поле `joinedAt` в `voice_room_state`, Unix мс): локальные
  часы клиента не дают одного порядка у всех. Нет поля (старый сервер) —
  запасной «первый раз увидел»; рестарт сервера обнуляет стаж. Своя плитка
  всегда в видимых. Лимит `MAX_VOICE_TILES` (16), при показе экрана
  `MAX_VOICE_TILES_WITH_STAGE` (8). Плитки держат 16:9, колонки подбирает
  `fitVoiceTiles` (не CSS auto-fit) — пустое место остаётся пустым.
