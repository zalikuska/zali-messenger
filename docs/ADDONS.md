# Аддоны хаба — руководство автора

Аддон — мини-приложение, которое пользователь ставит в хаб одним файлом `.zali` и
запускает оттуда же на всё окно: мини-игра, запись голоса, сборщик модов, лаунчер
программы с компьютера. Аддон — это **интерфейс** (HTML/CSS/JS в песочнице) и, по
желанию, **бэкенд**: встроенные инструменты приложения (`window.zali`) или собственная
программа-процесс. Всё, что выходит за песочницу, выдаётся по разрешениям.

Готовые примеры — `examples/addons/` (змейка, голосовые заметки, лаунчер). Собрать
любой из них:

```bash
python3 scripts/addon_pack.py examples/addons/snake snake.zali
```

Где что в коде: формат и манифест — `web/src/modules/addon_format.js`, SDK —
`web/src/modules/addon_sdk.js`, хост — `web/src/interface/addons_*.js`, нативная часть —
`apps/windows/src/native/addon{s,_elevated}.rs`, `apps/macos/.../Services/Addon{Store,Elevated}.swift`,
`apps/android/.../AddonStore.kt`. Подписи и казна аддонов — `server/src/addons.rs`,
`web/src/interface/addons_{coins,signing}.js`, `scripts/addon_sign.py`, раздел 10.
Облако на сервере и внешние серверы — `server/src/addon_cloud.rs`,
`web/src/interface/addons_cloud.js`, `scripts/addon_cloud.py`,
`scripts/addon_dev_server.py`, раздел 11. Проверки — `scripts/security_doctor/check_addons.mjs`, `tests/addons.rs`.

## 1. Файл `ZALIEXTN`

Тот же контейнер, что у `.zali` сообщений (`sdk/Rust` `ZaliSession`, `sdk/Swift` `ZaliArc`),
другой магик и без шифрования: файл должен читаться до установки, чтобы показать
пользователю, что аддон просит.

```
"ZALIEXTN"            8 байт
version   u8          = 1
id        u8 len+utf8 — id аддона (информационно, истина — в манифесте)
dom       u8 len+utf8 — "addon"
flags     u8          = 0 (шифрование запрещено)
count     u32 LE
count раз: nameLen u16 LE | name utf8 | size u64 LE | stored u64 LE (= size) | данные
```

Ограничения (их одинаково проверяют веб и нативные оболочки):

- файл ≤ 32 МБ, записей ≤ 2000, `manifest.json` ≤ 64 КБ;
- путь — сегменты `[A-Za-z0-9._-]+` через `/`, без `.` и `..`, без ведущего и
  завершающего `/`, ≤ 255 байт; имена, отличающиеся только регистром, — дубликаты;
- `flags ≠ 0`, `stored ≠ size`, лишние байты после последней записи — отказ.

Установка и управление — вкладка хаба «Аддоны»; на главной хаба у каждого установленного
аддона своя плашка быстрого запуска (фон — `background` в манифесте, см. раздел 2).

Упаковщик `scripts/addon_pack.py <папка> <файл.zali>` проверяет всё это и манифест
заранее; скрытые файлы (`.git`, `.DS_Store`) пропускает.

То же делает вкладка хаба «Упаковщик» (`web/src/interface/addons_pack.js`): выберите ZIP
с исходниками — `manifest.json` в корне или внутри единственной папки, скрытые и
служебные файлы (`.git`, `__MACOSX`, `Thumbs.db`) пропускаются, пути и манифест
проверяются теми же правилами — и получите `.zali`: установить, сохранить или
подписать. ZIP читает `web/src/modules/zip_reader.js` (stored и deflate; ZIP64 и
шифрование не поддерживаются).

## 2. Манифест `manifest.json`

```json
{
  "zaliAddon": 1,
  "id": "org.example.snake",
  "name": "Змейка",
  "version": "1.0.0",
  "description": "Классическая змейка",
  "author": "Имя",
  "icon": "icon.svg",
  "entry": "index.html",
  "permissions": ["cache", "network"],
  "network": ["api.example.com"],
  "backend": {
    "type": "process",
    "commands": {
      "macos-arm64": "bin/macos-arm64/backend",
      "macos-x64": "bin/macos-x64/backend",
      "windows-x64": "bin/windows-x64/backend.exe"
    },
    "args": []
  }
}
```

| Поле | Обязательно | Правило |
|---|---|---|
| `zaliAddon` | да | ровно `1` |
| `id` | да | `^[a-z0-9][a-z0-9._-]{2,63}$`, без `..`; это же имя папки на диске. Аддон с тем же `id` ставится поверх (обновление) |
| `name` | да | до 64 символов |
| `version` | да | `^[0-9A-Za-z][0-9A-Za-z.+-]{0,31}$`, например `1.0.0` |
| `description`, `author` | нет | до 300 и 80 символов |
| `entry` | нет | `.html` внутри файла, по умолчанию `index.html` |
| `icon` | нет | png, svg, webp или jpeg внутри файла |
| `background` | нет | png, svg, webp или jpeg внутри файла, до 512 КБ. Фон плашки быстрого запуска на главной хаба: показывается от левого до правого края плашки, поверх него — затемнение слева под текст. Без него плашка обычная |
| `permissions` | нет | список из каталога ниже; неизвестное разрешение — отказ (старое приложение не должно молча выдать меньше) |
| `network` | с `network` | до 16 хостов без схемы и пути: `api.example.com`, `*.example.com`, `host:8443`. С разрешением `network.any` список не нужен |
| `backend` | с `process` | `type: "process"`, `commands` — платформа → путь внутри файла, `args` — до 32 строк по 256 символов |

Платформы `backend.commands`: `macos-arm64`, `macos-x64`, `windows-x64`, `windows-arm64`.
Для macOS кладите обе архитектуры: запускается только программа своей платформы.

## 3. Разрешения

Без разрешений аддон рисует свой интерфейс, читает свои файлы (`zali.assets`) и хранит
настройки на этом устройстве (`zali.storage`, до 1 МБ; на серверах — `cloud`, раздел 11). Открыть файл, который выбрал пользователь, можно
обычным `<input type="file">` — без разрешений.

| Разрешение | Уровень | Что даёт | Где работает |
|---|---|---|---|
| `cache` | обычный | свои файлы в кеше приложения, до 256 МБ | везде |
| `notifications` | обычный | уведомление от имени «Аддон «имя»», не чаще раза в 5 с | везде |
| `clipboard` | обычный | копирование текста, пока аддон открыт | везде |
| `files` | обычный | сохранение файла через загрузки, не чаще раза в 2 с, пока аддон открыт | везде |
| `microphone` | обычный | запись звука (пишет приложение, аддону отдаёт байты), до 60 минут и 64 МБ | где есть микрофон |
| `network` | обычный | `fetch`/`WebSocket` к хостам из `network` (только https/wss) | везде |
| `cloud` | обычный | 10 МБ данных на **аддон** (на всех его пользователей вместе) на серверах ZaliMessenger: синхронизация и сбор данных; автор читает то, что сохранили пользователи. Нужны подпись аддона и вход в аккаунт (раздел 11) | везде, где есть вход в аккаунт |
| `coins` | обычный | видеть баланс ZaliCoin человека и предлагать перевести монеты на баланс аддона; каждый перевод — только после подтверждения в окне приложения. Нужна подпись, раздел 10 | везде, где есть вход в аккаунт |
| `network.any` | **повышенный** | `fetch`/`WebSocket` к **любым** серверам, включая адрес, который человек введёт сам, и обычный `http://`/`ws://` к локальной сети (раздел 11) | macOS, Windows |
| `fs.read` | **повышенный** | чтение любых файлов и папок | macOS, Windows |
| `fs.write` | **повышенный** | создание, запись и удаление любых файлов | macOS, Windows |
| `launch` | **повышенный** | открыть файл или папку системой, запустить программу | macOS, Windows |
| `process` | **повышенный** | запуск собственной программы-бэкенда | macOS, Windows |

Если хоть одно разрешение аддона на платформе недоступно (повышенные в браузере и на
Android, микрофон без устройства, `process` без программы под эту систему), аддон на ней
не запускается, а хаб пишет почему. Делайте отдельные аддоны, если нужна и «лёгкая»
версия для телефона.

### Подтверждения

- **Установка.** Диалог приложения: иконка, имя, версия, автор, размер, отпечаток
  SHA-256 и список разрешений; повышенные выделены. Если они есть, следом показывается
  **системный** диалог (NSAlert на macOS, MessageBox на Windows) с их перечнем; по
  умолчанию выбрана «Отмена». Права оболочка читает из манифеста внутри файла сама и
  запоминает вместе с отпечатком файла.
- **Каждый запуск** аддона с повышенными правами — снова системный диалог. Оболочка
  сверяет отпечаток файла с подтверждённым при установке: подменённый на диске файл
  не запустится. Повышенные операции работают только в сессии этого запуска.
- **Обновление** (тот же `id`) — снова оба диалога: права привязаны к файлу, а не к `id`.

## 4. SDK `window.zali`

Хост кладёт SDK первым скриптом документа, до вашего кода. Все вызовы асинхронные и
возвращают `Promise`; ошибка — `ZaliAddonError` с полями `code` и `message`.

```js
const info = await zali.ready;
// {id, name, version, permissions, network, platform, visible, theme: {accent, background, text}}
// platform: 'macos' | 'windows' | 'android' | 'ios' | 'web'
```

| Вызов | Разрешение | Результат |
|---|---|---|
| `zali.ui.collapse()` / `close()` / `setTitle(text)` | — | свернуть (только пока аддон развёрнут; у свёрнутого — пустой вызов), закрыть, заголовок в верхней полосе (до 64 символов) |
| `zali.storage.get(key)` / `set(key, value)` / `remove(key)` / `keys()` / `clear()` | — | значения — любой JSON, ключ до 256 символов, всё вместе до 1 МБ |
| `zali.assets.read(path)` / `text(path)` / `url(path)` | — | `Uint8Array`, строка, `blob:`-URL файла из вашего архива |
| `zali.cache.write(path, data)` | `cache` | `data` — `Uint8Array`, `ArrayBuffer`, `Blob` или строка, до 32 МБ за раз |
| `zali.cache.read(path)` / `text(path)` | `cache` | `Uint8Array` / строка или `null`, если файла нет |
| `zali.cache.list(prefix)` / `remove(path)` / `usage()` | `cache` | `list` → `[{path, size}]`; `usage()` → `{bytes, quota, files}` |
| `zali.cloud.get(key)` / `set(key, value)` | `cloud` | JSON-значение в личной области человека; `get` несуществующего — `null` |
| `zali.cloud.getBytes(key)` / `setBytes(key, data)` | `cloud` | двоичные данные (`Uint8Array`, `ArrayBuffer`, `Blob`, строка) |
| `zali.cloud.remove(key)` / `keys()` / `clear()` / `usage()` | `cloud` | `remove` → `true`, если ключ был; `keys` → `[ключи]`; `clear` → число стёртых; `usage` → `{bytes, quota, mine, mineQuota, keys, isOwner}` |
| `zali.cloud.shared.*` | `cloud` | то же для общей области: читают все, пишет только автор |
| `zali.cloud.collect.list({offset, limit})` / `get(user, key)` / `getBytes(user, key)` | `cloud` | только автору: данные пользователей |
| `zali.notify({title, body})` | `notifications` | `{shown}` |
| `zali.coins.balance()` | `coins` | `{balance, held}` — баланс человека |
| `zali.coins.treasury()` | `coins` | `{signed, trusted, official, owner, isOwner, deposited, available}` — сколько человек перевёл аддону и сколько может забрать; автору ещё `balance`, `withdrawable`, `locked`, `nextUnlock` |
| `zali.coins.deposit({amount, note})` | `coins` | `{ok, deposited, balance}` — после подтверждения в окне приложения; `amount` — целое > 0, `note` до 140 символов |
| `zali.coins.withdraw({amount})` | `coins` | `{ok, withdrawn, balance, available}` — человек забирает из аддона на свой баланс; без подтверждения и без удержания (см. раздел 10) |
| `zali.clipboard.writeText(text)` | `clipboard` | до 1 МБ |
| `zali.files.save({name, data, mimeType})` | `files` | `true` |
| `zali.mic.start()` / `stop()` / `cancel()` | `microphone` | `stop()` → `{data: Uint8Array, mimeType, durationMs}` |
| `zali.fs.paths()` | `fs.read` или `fs.write` | `{home, documents, downloads, desktop, temp, addonData, separator, platform}` |
| `zali.fs.read(path)` / `readText(path)` | `fs.read` | файл до 32 МБ |
| `zali.fs.list(path)` | `fs.read` | до 5000 записей `{name, type: 'file'\|'dir'\|'other', size, modifiedMs}` |
| `zali.fs.stat(path)` | `fs.read` | `{exists, type, size, modifiedMs}` |
| `zali.fs.write(path, data, {append})` / `mkdir(path)` / `remove(path, {recursive})` | `fs.write` | `true`; `remove` несуществующего — `false` |
| `zali.system.open(path)` | `launch` | открыть файл или папку программой по умолчанию |
| `zali.system.exec(path, args, {cwd})` | `launch` | запустить программу → `{pid}`; вывод не возвращается |
| `zali.backend.send(obj)` / `restart()` | `process` | строка JSON в stdin бэкенда |
| `zali.on(event, fn)` / `zali.off(event, fn)` | — | подписка; `on` возвращает функцию отписки |

Пути в `zali.fs` и `zali.system` — только полные (`/Users/me/...`, `C:\Games\...`). Корень
диска, папки первых двух уровней (`/Users`, `C:\Windows`), домашняя папка и её предки
`fs.remove` не удаляет. Пути в `cache` — те же сегменты, что внутри архива.

События:

| Событие | Данные | Когда |
|---|---|---|
| `visibility` | `{visible}` | аддон свернули или развернули. Свёрнутый аддон работает дальше |
| `backend` | объект из строки stdout (или `{text}`, если строка не JSON) | бэкенд написал строку |
| `backend-exit` | `{code}` | бэкенд завершился |
| `backend-error` | `{message}` | строка бэкенда больше 1 МБ и т. п. |

Коды ошибок: `permission_denied`, `bad_params`, `bad_path`, `not_found`, `quota`,
`too_large`, `rate_limited`, `not_visible` (буфер, сохранение и запись звука — только пока
аддон развёрнут), `busy`, `unsupported`, `denied`, `cancelled`, `not_recording`,
`unknown_method`, `failed`. Одновременно в работе до 64 вызовов. Для `zali.cloud.*`
ещё: `revoked` (сборка отозвана), `not_signed` (аддон не подписан или его нет в реестре), `forbidden` (общая
область и сбор — только автору), `quota` (не хватило места в облаке), `offline` (нет
связи с сервером), `unsupported` (в аккаунт не вошли), `rate_limited` (больше 40
обращений за 10 секунд). Для `zali.coins.*`
ещё: `not_signed` (файл не подписан, подпись не сошлась или автора нет в реестре),
`not_registered`, `insufficient_funds`, `over_limit` (больше, чем человек может забрать),
`offline` (нет связи с сервером).

## 5. Собственный процесс

Для лаунчеров, сборщиков модов и всего, чему нужен нативный код.

- Программа — **один самодостаточный исполняемый файл** под платформу из
  `backend.commands`. При запуске аддона оболочка распаковывает только его в
  `<данные приложения>/addons/<id>/bin/<отпечаток>/` и при каждом запуске сверяет с
  архивом. Библиотеки рядом с ним не распаковываются — собирайте статически или кладите
  нужное в `zali.cache` / на диск через `fs.write`.
- Стартует после системного подтверждения запуска, завершается при остановке аддона
  и выходе из приложения. Свёрнутый аддон бэкенд не останавливает.
- Обмен — **JSON по строкам**: `zali.backend.send(obj)` → одна строка в stdin; каждая
  строка stdout → событие `backend`. Строка до 1 МБ. stderr уходит в лог оболочки.
- Окружение: `ZALI_ADDON_ID`, `ZALI_ADDON_DIR` (папка распакованной программы),
  `ZALI_ADDON_DATA` (папка данных аддона; она же текущая папка).
- Программа работает с правами пользователя: поэтому `process` — повышенное разрешение.
- **macOS arm64** запускает только подписанные программы. Rust и Go подписывают сборку
  ad-hoc сами; иначе — `codesign -s - bin/macos-arm64/backend` перед упаковкой.

Минимальный бэкенд на Python-подобном псевдокоде:

```
for line in stdin:
    msg = json.loads(line)
    stdout.write(json.dumps({"reply": msg}) + "\n"); stdout.flush()
```

## 6. Песочница интерфейса

- `<iframe sandbox="allow-scripts allow-pointer-lock">` без `allow-same-origin`: у аддона
  нет доступа к окну приложения, `localStorage`, IndexedDB и cookies; всплывающие окна,
  формы, загрузки и переход на другую страницу запрещены. Попытка увести фрейм на
  другую страницу останавливает аддон. Камера, микрофон и геолокация фрейму не даны —
  микрофон только через `zali.mic`.
- Документ собирает хост. `<script src>` и `<link rel=stylesheet>` встраиваются из
  архива, `url(...)` в CSS и `src` у `img`/`audio`/`video`/`source` превращаются в
  `data:`-URL. Ссылки на внешние скрипты удаляются. `<base>` и `<meta http-equiv>`
  удаляются. ES-модули с `import` между файлами не работают — собирайте в один файл.
  Картинки, которые код создаёт сам, берите через `await zali.assets.url(path)`.
- CSP (ужесточить своим тегом можно, ослабить — нет):
  ```
  default-src 'none'; script-src 'unsafe-inline' 'unsafe-eval' 'wasm-unsafe-eval' blob:;
  style-src 'unsafe-inline' blob: data:; img-src data: blob: [https://хосты];
  media-src data: blob: mediastream: [https://хосты]; font-src data: blob:;
  connect-src data: blob: [https://хосты wss://хосты]; worker-src blob:; child-src blob:;
  frame-src 'none'; object-src 'none'; form-action 'none'; base-uri 'none'
  ```
  Хосты подставляются из `network`, только если есть разрешение `network`.
- WebRTC (`RTCPeerConnection`, `RTCDataChannel`) CSP не покрывает, поэтому SDK
  убирает эти конструкторы из окна аддона до его кода: в песочнице их нет вовсе.
  Звук — только через `zali.mic`.
- Тема: хост добавляет CSS-переменные `--zali-accent`, `--zali-accent-rgb`, `--zali-bg`,
  `--zali-surface`, `--zali-text`, `--zali-text2`, `--zali-text3`, `--zali-border`,
  `--zali-danger`, `--zali-radius`, `--zali-font`. Используйте их, чтобы аддон выглядел
  частью приложения.
- Если документ не вызвал SDK за 15 секунд (`zali.ready` вызывается сам при загрузке
  SDK), хаб покажет ошибку запуска.

**Помните про сеть.** Всё, что аддону доступно (кеш, файлы с диска, запись микрофона),
он может отправить на хосты из `network`. Поэтому пользователь видит список хостов в
диалоге установки, а аддону с `fs.read` и `network` вместе стоит доверять как программе.

## 7. Интерфейс в приложении

- Хаб, секция «Аддоны»: «Установить аддон», у каждого — «Открыть» и меню «⋯» с
  разрешениями, отпечатком и «Удалить». У запущенного — «Развернуть» и «Остановить».
- Открытый аддон занимает всё окно под верхней полосой. Кнопка «Свернуть» — в полосе
  сразу после кнопок окна (на телефоне — полоса над аддоном). Свёрнутый аддон виден в
  полосе плашкой с именем; клик разворачивает.
- Одновременно работают до 4 аддонов, развёрнут один. Входящий звонок и переход в
  чаты, настройки или ZaliCoin сворачивают аддон.
- Установить аддон можно и перетаскиванием `.zali` на раздел «Аддоны». Только что
  установленный помечен «Новый». Пока аддон запускается, кнопка «Открыть» занята.
- «⋯» → сведения: разрешения, отпечаток, размер данных аддона, «Очистить данные»
  (настройки и кеш; запущенный аддон при этом останавливается) и «Удалить аддон».
- Если аддон не запустился или упал, на его месте — «Перезапустить» и «Закрыть аддон».

## 8. Хранение

- С нативной оболочкой: `<данные приложения>/addons/<id>/` — `addon.zali`, `meta.json`,
  `grant.json` (отпечаток и подтверждённые повышенные права), `data/` (`kv.json`
  настроек и `cache/`), `bin/`.
- В браузере — IndexedDB.
- «Удалить» стирает папку аддона целиком, вместе с его данными.

## 9. Ограничения и дальше

- Подпись (раздел 10) открывает аддону ZaliCoin и закрепляет его за автором, но не
  делает его безопасным: доверие к коду по-прежнему — к файлу, который пользователь
  выбрал сам; отпечаток SHA-256 виден в диалоге. Каталога аддонов пока нет.
- 32 МБ на файл аддона и на одну операцию с файлом (мост передаёт base64).
- Нет ES-модулей между файлами; нет повышенных прав на Android и в браузере.

## 10. Подписи, автор и ZaliCoin аддона

Аддон может принимать ZaliCoin на свой баланс (игровая валюта, донаты, платные функции).
Деньги — единственное, что аддон делает «вовне» приложения без права выхода из песочницы,
поэтому перед ними стоят подпись, запись об авторе на сервере и подтверждение человека.

### Две подписи

Подпись — файл `zali-signature.json` внутри контейнера. Он не входит в отпечаток
содержимого, поэтому его можно заменить, не меняя аддон:

```json
{"zaliSignature": 1, "kind": "self", "alg": "ES256", "publicKey": "<base64, 65 байт>",
 "id": "org.example.game", "version": "1.2.0", "owner": "login", "digest": "<sha-256 hex>",
 "signedAt": 1760000000000, "signature": "<base64, 64 байта r‖s>"}
```

- **`self` — самоподпись.** Выдаёт сервер приложения, а не автор: закрытый ключ лежит
  только на сервере и никуда не отдаётся, инструмент открыт каждому вошедшему
  (Хаб → «Подпись аддонов»). Это **не** поручительство приложения за аддон: предупреждение
  при установке и при переводе остаётся строгим. Подпись даёт две вещи — аддон можно
  пополнять, и он закрепляется за автором.
- **`official` — официальная.** Приложение за такой аддон поручается: при переводе
  человек видит обычное уведомление, без предупреждения об обмане. Выдаётся по заявке
  и после ручного одобрения оператором сервера (см. ниже); либо офлайн-инструментом
  разработчиков с приватным ключом, которого нет в репозитории (`ops/keys/`, в
  `.gitignore`). Публичный ключ зашит в клиент (`addon_format.js`), сервер
  (`server/src/addons.rs`) и `scripts/addon_sign.py` — менять его нужно во всех
  трёх сразу; это проверяет `check_addons.mjs`.

Что подписывается: `zali-addon-sig:v1\n{kind}\n{id}\n{version}\n{owner}\n{digest}\n{signedAt}`;
`digest` — SHA-256 от `zali-addon-content:v1\n` и записей контейнера (кроме файла подписи),
отсортированных по пути: `u32be(len path) · path · u64be(len data) · data`. Алгоритм —
ECDSA P-256 + SHA-256, подпись — «сырые» r‖s. Любая правка файла после подписания,
подпись под другой `id` или версией, подмена вида подписи ломают её: файл показывается
как «подпись недействительна».

Состояния подписи в приложении: `none` — нет; `self`; `official`; `unverified` — похоже на
самоподпись, но ключа сервера нет или он чужой (файл подписан другим сервером); `invalid`.
Только `self` и `official` пускают к деньгам.

### Самоподпись в хабе

Хаб → вкладка «Подпись аддонов»: выбираете `.zali`, приложение считает отпечаток и
отправляет серверу `id`, версию и отпечаток (`POST /api/addons/sign`) — сам файл на сервер
не уходит. Сервер подписывает от вашего имени и **закрепляет `id` за вами**: первый, кто
подписал `id`, становится его автором, и другой аккаунт этот `id` уже не подпишет
(официальная подпись может перехватить `id`; официальный аддон самоподписью не
понизить). Готовый файл `<id>-<версия>.signed.zali` сохраняется на диск — раздавайте его.
Лимиты: 100 аддонов на аккаунт, 30 подписей в час.

Автору во вкладке видны «Мои аддоны»: установки, запуски и казна, кнопка «Управление».

### Заявка на официальную подпись

Там же: выбрать файл, уже подписанный вами, → «Запросить официальную». Заявка относится
к **конкретной сборке** (id + версия + отпечаток) и содержит короткую заметку. Её
рассматривает оператор сервера вручную (`scripts/addon_review.py list / approve / reject`,
нужен `RELEASE_ADMIN_TOKEN`). Когда заявку одобрили, автору приходит уведомление, и тот же
файл можно подписать официально — «Получить официальную подпись». Другой отпечаток или
версия — новая заявка. Подписывает серверный официальный ключ
(`addon_official_key.pem` в data dir или `ZALI_ADDON_OFFICIAL_KEY_FILE`; публичная часть
обязана совпадать с зашитой); без ключа одобренная заявка ждёт, подпись вернёт
`official_unavailable`. После официальной подписи `id` самоподписью уже не подписать.

### Что доходит до денег

Перевод принимается, только если сошлись оба условия:

1. подпись в файле верна (`self` или `official`);
2. запись об авторе в реестре сервера совпадает с файлом: тот же автор, тот же вид
   подписи и отпечаток ключа.

Подпись в файле одна не пускает: файл, подписанный чужим ключом или ключом другого
сервера, к казне не допускается. Тот же проверяет сервер при `deposit`.

### Окно перевода

`zali.coins.deposit({amount, note})` всегда открывает окно приложения — отключить или
пропустить его нельзя. В нём: рисунок (монета → значок аддона), сумма, остаток баланса,
комментарий аддона и предупреждение:

- **подписан официально** — «вы перечисляете свои ZaliCoin на баланс приложения»;
- **иначе** — «отправляя деньги, вы не можете быть уверены, что вас не обманут»,
  имя автора и отметка «понимаю риск», без которой кнопка «Перевести» неактивна.

Перевод — только пока аддон развёрнут, не чаще раза в 3 секунды, не больше баланса;
каждая операция идёт с ключом идемпотентности, повтор не списывает дважды.

### Вывод: человек и разработчик

- **Человек** (`zali.coins.withdraw`, `POST /api/addons/:id/payout`) забирает из аддона на
  свой баланс **то, что сам перевёл**, — сразу, без удержания и без подтверждения. Чужое
  получить нельзя, поэтому второй аккаунт автора ничего не вытянет. Официальный аддон
  может платить и сверх внесённого человеком (призы), но не больше казны.
- **Разработчик** выводит из казны через окно «Управление» в хабе
  (`POST /api/addons/:id/withdraw`) — **только то, что внесено больше недели назад**
  (`ZALI_ADDON_HOLD_SECS` на сервере — для тестов; по умолчанию 7 суток). Выплаты
  пользователям тоже уменьшают доступное к выводу. Неделя — ограничение разработчика, а не
  пользователя аддона.

Взносы копятся в казне аддона — таком же держателе эмиссии, как баланс и казна сервера:
общая сумма монет не меняется (`/api/coins/distribution` показывает её в `addonTreasuries`).

### Статистика автора

Только автору (`GET /api/addons/:id/manage`): установок сейчас и когда-либо, активных людей
за 7 и 30 суток, запусков за 7 суток и всего, график запусков за 14 суток. Это счётчики
без имён: клиенты шлют события `install` / `update` / `launch` / `remove`
(`POST /api/addons/:id/events`, не чаще раза в 5 секунд), сервер учитывает их только для
аддонов, у которых есть автор в реестре. Когда кто-то пополняет казну, автору приходит
событие `addon_coins` по WebSocket.

### Магазин аддонов

Витрина лежит в хабе, вкладка «Аддоны» (над списком установленных). Попасть в неё может
только **официально подписанная** сборка (`kind: "official"`), и только от владельца `id`
в реестре — самоподписанный аддон в магазин не берётся.

**Публикация** — в том же окне, что и подпись («Подпись аддонов»): после выбора файла под
ним появляется блок «В магазин» с переключателем «Бесплатно / Платно» и полем цены. Кнопка
отправляет файл как есть (`POST /api/addons/store/publish`, `{fileBase64, price,
summary?}`); отдельной формы описания нет — берутся `name`, `description`, `author`,
`permissions`, `icon` и `background` из манифеста. Сервер сам перепроверяет всё, чему
нельзя верить клиенту: подпись официальным ключом, совпадение `id`/`version` с манифестом,
владельца, пересчитанный отпечаток содержимого (`contentDigest`) и что сборка не отозвана.
Новая версия публикуется тем же вызовом и заменяет карточку; цену и описание можно менять
без перезаливки (`POST /:id/update`), снять с витрины — `DELETE /:id`.

**Цена** — целое число ZC от 0 до 10 000 (0 — бесплатно). Разовая покупка: монеты
переходят от покупателя к автору в одной транзакции (запись в `coin_transactions`,
ключ `store:{id}:{покупатель}` — повторная покупка невозможна), а право на аддон — запись
в `addon_store_purchases`. Эмиссия не меняется, автору приходит `addon_coins` с
`kind: "sale"`. Бесплатный аддон «покупается» тем же вызовом без перевода.

**Скачивание** (`GET /:id/download`) отдаёт файл тому, кто купил (или всем — если цена 0);
иначе `402 payment_required`. Снятый с витрины аддон остаётся доступным купившим, а
отозванная сборка (раздел 11) скрывается из магазина и не отдаётся никому. Скачанный файл
приложение устанавливает обычным путём — подпись проверяется на клиенте заново, так что
сервер магазина не может подсунуть чужую сборку.

Ограничения: файл ≤ 16 МБ, описание ≤ 300 символов, иконка ≤ 256 КБ, фон ≤ 512 КБ,
не больше 50 карточек на автора и 20 публикаций в час. Картинки отдаются отдельным
запросом (`GET /:id/assets`), чтобы список оставался лёгким.

| Метод и путь | Кто | Что |
|---|---|---|
| `GET /api/addons/store` | вошедший | витрина: `?q=&filter=all\|free\|paid\|owned&limit=&offset=` → `{items, balance}` |
| `POST /api/addons/store/publish` | владелец `id` | опубликовать или заменить версию |
| `POST /api/addons/store/:id/update` | владелец | цена и описание |
| `DELETE /api/addons/store/:id` | владелец | снять с витрины |
| `GET /api/addons/store/:id/assets` | вошедший | иконка и фон как data-URL |
| `POST /api/addons/store/:id/buy` | вошедший | купить; 400 `insufficient_funds` |
| `GET /api/addons/store/:id/download` | купивший | файл `.zali` (base64); 402 `payment_required` |

Фон из `background` манифеста показывает и быстрая плитка аддона на главной хаба, и обложка
карточки в магазине. Код — `server/src/addon_store.rs`, клиент —
`web/src/interface/addons_store_ui.js` и блок публикации в `addons_signing.js`; тесты —
`tests/addon_store.rs`. **Сервер выкатывается раньше клиента**: старый сервер не знает
маршрутов магазина, и вкладка покажет ошибку загрузки.

### Закрепление и отвязка `id`

`id` закрепляется за аккаунтом, который первым его подписал. Пока он закреплён:

- подписать аддон с таким же `id` другим аккаунтом нельзя (`409 addon_taken` — в
  ответе назван владелец);
- приложение не установит файл с таким `id`, если он не подписан владельцем (иначе
  «подделка» занимала бы место настоящего аддона в хабе); собственную неподписанную
  версию владелец ставить может.

Владелец отпускает имя в «Подпись аддонов» → «Управление» → «Отвязать id»
(`POST /api/addons/:id/unbind`). Чтобы отвязка не стала способом забрать чужое:

- в казне аддона должно быть пусто (`409 treasury_not_empty`): сначала верните вклады
  и выведите остаток;
- журнал вкладов, статистика и заявки на официальную подпись уходят в архив
  (`<id>#unbound-<время>`): новый владелец начинает с нуля, а «доступно к возврату»
  старых вкладчиков не может зацепить его казну;
- облако аддона стирается целиком (раздел 11);
- официальный `id` владельцу отвязывать нельзя (`403 addon_official`) — только
  разработчикам ZaliMessenger.

После отвязки следующий, кто подпишет аддон с этим `id`, становится владельцем.
Отозванные сборки (раздел 11) остаются отозванными.

## 11. Облако ZaliMessenger и внешние серверы

Данные аддона можно держать в двух местах, кроме локального `zali.storage`:

| | Облако ZaliMessenger | Внешний сервер |
|---|---|---|
| Разрешение | `cloud` (обычное) + **подпись аддона** | `network.any` (**повышенное**) |
| Где лежит | на сервере приложения | на сервере автора или человека |
| Объём | **10 МБ на аддон** — на всех его пользователей вместе; у человека личная доля 1 МБ; до 1000 ключей в области и 10 000 на аддон | сколько даст ваш сервер |
| Кто видит | человек — свои; все — общую область; **автор — данные всех пользователей** | кто имеет доступ к серверу |
| Платформы | везде, где есть вход в аккаунт | macOS, Windows (системный диалог при каждом запуске) |

### Облако: `zali.cloud`

Облако — хранилище **приложения**, а не личный диск человека: для аддонов, которым
нужна синхронизация между устройствами и людьми и сбор данных от пользователей.
Работает только у подписанного аддона (раздел 10): самоподписи достаточно, она
закрепляет `id` за автором. Без подписи — `not_signed`.

Три области:

| Область | API | Кто читает | Кто пишет |
|---|---|---|---|
| личная (по умолчанию) | `zali.cloud.get/set/…` | человек; **автор аддона** | человек, до 1 МБ |
| общая | `zali.cloud.shared.get/set/…` | все пользователи аддона | только автор |
| сбор | `zali.cloud.collect.*` | только автор | — |

```js
// Личная область человека — синхронизация между его устройствами.
await zali.cloud.set('progress', { level: 7 });          // JSON
await zali.cloud.get('progress');                         // значение или null
await zali.cloud.setBytes('save.bin', new Uint8Array(…));
await zali.cloud.getBytes('save.bin');                    // Uint8Array или null
await zali.cloud.keys(); await zali.cloud.remove('k'); await zali.cloud.clear();
const u = await zali.cloud.usage();
// {bytes, quota} — пул аддона; {mine, mineQuota} — доля человека; keys; isOwner

// Общая область — читают все, пишет автор (новости, наборы уровней, настройки).
const news = await zali.cloud.shared.get('news');
if (u.isOwner) await zali.cloud.shared.set('news', { text: 'Новый уровень' });

// Сбор — автор читает то, что пользователи сохранили у себя.
const page = await zali.cloud.collect.list({ offset: 0, limit: 100 });
// {total, users, bytes, offset, items: [{user, key, kind, size, updatedAt}]}
const answer = await zali.cloud.collect.get('alice', 'survey');
```

- Ключ — от 1 до 256 байт без управляющих символов; `/` — обычный символ. Под одним
  ключом лежит либо JSON, либо байты: `get` байтового ключа и наоборот — `bad_params`.
- Пул 10 МБ — общий потолок аддона. Чтобы один человек не занял его целиком, у каждого
  своя личная доля — 1 МБ; общая область делит пул с личными. Не хватило места —
  `quota`; ничего не записывается наполовину. Замена значения освобождает старый размер.
- Автор — владелец записи об аддоне в реестре серверов (раздел 10), а не тот, чей
  файл запущен: писать в общую область и собирать данные получится, только войдя в
  аккаунт автора. Остальным сервер ответит `forbidden`.
- **Автор видит то, что аддон сохранил о людях.** Это назначение хранилища, и
  человек предупреждён: в тексте разрешения «Облако ZaliMessenger» при установке
  сказано, что автор может прочитать сохранённое о нём. Человек в любой момент стирает
  свою область: «⋯» → сведения → «Удалить мои данные из облака». Не кладите в облако то,
  о чём вы не сказали людям.
- Данные не зависят от файла аддона: переустановка, обновление и удаление аддона
  облако **не** стирают.
- На сервере данные хранятся в открытом виде (не сквозное шифрование, как сообщения).
  Для секретов шифруйте значение сами.
- Сервер не видит файл аддона, поэтому подпись сверяет приложение (как для ZaliCoin):
  подпись, автор и ключ в файле должны совпасть с записью в реестре. Сервер гарантирует
  остальное: человек пишет только в свою область, а общая и чужие данные — только по
  праву автора.

### Внешние серверы: `network.any`

Разрешение `network` перечисляет хосты заранее. Если адрес сервера не известен автору
(человек поднимает свой, как у `scripts/addon_dev_server.py`), нужен `network.any`:

```json
{ "permissions": ["network.any"] }
```

- Политика безопасности страницы аддона открывает `connect-src` для любых `https:`/`wss:`
  и, для серверов в своей сети, `http:`/`ws:`; картинки и медиа — только `https:`.
  Остальное (скрипты, фреймы, формы) закрыто так же.
- Это **повышенное** разрешение: при установке и **при каждом запуске** показывается
  системный диалог со строкой «обращаться к любым серверам в интернете и передавать им
  данные аддона». В браузере и на Android такой аддон не запустится.
- Аддон с `network.any` и `fs.read` вместе может отправить любые файлы человека
  кому угодно. Ставьте такой аддон только от автора, которому доверяете.
- Если хосты известны заранее, выбирайте `network` со списком: он обычный, не требует
  системного диалога и работает везде.

### Инструменты

- `scripts/addon_pack.py` проверяет `cloud`, `network.any` и список `network` так же,
  как приложение; `--check` проверяет готовый файл.
- `scripts/addon_cloud.py` — облако из командной строки: `usage`, `ls`, `get`, `put`
  (JSON или `--file`), `rm`, `clear`, `--shared` для общей области и `collect` для автора.
  Удобно положить тестовые данные и посмотреть, что записал аддон, не запуская приложение.
- `scripts/addon_dev_server.py` — образцовый внешний сервер (ключ → JSON, CORS,
  необязательный токен) для отладки аддонов с `network.any`.
- Примеры: `examples/addons/cloud-notes` (облако; перед запуском подпишите файл) и
  `examples/addons/external-sync` (внешний сервер, адрес вводит человек).

### Эндпоинты облака

Все требуют вход в аккаунт и аддон в реестре (`403 not_signed`); ответы с ошибкой —
`{code, message}`. `scope` — `user` (по умолчанию) или `shared`.

| Метод | Путь | Тело / ответ |
|---|---|---|
| `GET` | `/api/addons/:id/cloud?scope=` | `{scope, bytes, quota, mine, mineQuota, keys, maxKeys, isOwner, items: [{key, kind, size, updatedAt}]}` |
| `GET` | `/api/addons/:id/cloud/item?key=&scope=` | `{kind: "json"\|"bytes", value, size}` или 404 |
| `PUT` | `/api/addons/:id/cloud/item?key=&scope=` | `{kind, value}` (`bytes` — base64) → `{ok, bytes, quota, mine, mineQuota, keys}`; 413 `quota`; в `shared` — только автору |
| `DELETE` | `/api/addons/:id/cloud/item?key=&scope=` | `{ok, removed}` |
| `DELETE` | `/api/addons/:id/cloud?scope=` | `{ok, removed}` — стереть свою область (`shared` — автору) |
| `GET` | `/api/addons/:id/cloud/audit` | `{reads, listings, lastAt}` — сколько раз автор читал мои данные и просматривал список |
| `POST` | `/api/admin/addons/revoke` | оператору: `{addonId, digest, reason, restore}` — отозвать сборку или вернуть; в `GET /api/addons/:id` отозванные — `revoked: [digest]` |
| `GET` | `/api/addons/:id/cloud/collect?offset=&limit=` | автору: `{total, users, bytes, offset, items: [{user, key, kind, size, updatedAt}]}` |
| `GET` | `/api/addons/:id/cloud/collect/item?user=&key=` | автору: `{kind, value, size}` или 404 |
