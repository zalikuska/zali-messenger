# Жалобы и модерация

Код: сервер — `server/src/moderation.rs` (тесты — `tests/moderation.rs`), клиент —
`web/src/interface/moderation_report.js` (жалоба в ленте) и
`web/src/interface/support_hub.js` (хаб → «Поддержка»). Таблица наказаний живёт в
одном месте — `CATEGORIES` в `moderation.rs`; клиент получает её с сервера.

## Путь жалобы

1. ПКМ по чужому сообщению (на телефоне — долгое нажатие) → «Пожаловаться».
2. Лента переходит в режим жалобы, вместо поля ввода — панель с двумя режимами
   (сегменты). **Нарушение** — одна непрерывная зона ≤ 30 сообщений, всегда содержит
   сообщение, по которому нажали (его автор — обвиняемый); нажатие на сообщение
   дотягивает зону до него. **Важный контекст** — по желанию, до 5 отрезков где
   угодно (до нарушения, после), всего ≤ 30 сообщений; нажатие добавляет сообщение,
   повторное убирает отрезок. Слева от ленты — рельс каждой зоны, на концах —
   ручки-«пилюли» на линиях границ: тянутся мышью, пальцем, стрелками. У зон
   встык — одна общая двухцветная ручка, она двигает границу у обеих сразу. Панель —
   одна строка в облаке поля ввода. Всё, что не уйдёт на проверку, приглушено.
3. На сервер уходят зоны и по 20 сообщений вокруг каждого отрезка (объединение).
4. Сервер проверяет, что сообщения существуют, лежат в одной переписке и видны
   заявителю; отправителя и время берёт из БД. Тексты **канала** сверяет с архивами
   сам (ключ канала выводится из scope); расхождение → решает администрация.
   Тексты **личной переписки** сервер прочитать не может (E2E) и берёт со слов
   участника — как и предусматривает п. 5.2 Правил. Поэтому по ЛС Jev только
   советует: нарушение из ЛС не применяется автоматически, жалоба уходит
   администрации (`review`, причина `unverified`), меру назначает оператор.
5. Очередь → Jev → решение → мера → WS `moderation_standing` обвиняемому и
   `moderation_report_update` заявителям.

## Классификатор Jev

`POST {OPENROUTER_BASE_URL}/alpha/decisions`, модель `MODERATION_MODEL`
(по умолчанию `typesafe/jev-1.14`). Три вопроса: `violates` (noul — нарушил ли автор A
правила в красной зоне), `rule` (choice — какой пункт, `none` если никакой),
`severity` (score 0–3). Имена в запросе заменены метками (A — обвиняемый, R —
заявитель, U1… — остальные); длинный контекст обрезается с дальнего от зоны края
до ~28 КБ (дальше Jev уходит в медленный long-context режим).

| Ответ | Решение |
|---|---|
| `violates` ≥ 0,85 и пункт с вероятностью ≥ 0,5 | мера без человека |
| `violates` ≥ 0,75, пункт ≥ 0,85 и тяжесть ≥ 2 (три ответа согласны) | мера без человека |
| п. 3.1.1 и `violates` ≥ 0,6 | сразу серьёзное (защитная приостановка) |
| `violates` < 0,35 | «Нарушений не найдено»; если в зоне вложения — администрации |
| остальное, отказ модели, подделка текста | «Передано администрации» |

## Тиры мер

| Тир | Срок | Влияние |
|---|---|---|
| Предупреждение | 1 месяц | на состояние аккаунта не влияет |
| Нарушение | 2 месяца | засчитывается в шкалу |
| Серьёзное нарушение | 3 месяца | аккаунт приостановлен, пока действует |

Состояние аккаунта (полоса в «Поддержке») — функция действующих мер:

- нет действующих нарушений — «С аккаунтом все отлично!»;
- 1–2 нарушения — «Получено n из 3 предупреждений»;
- 3 и больше — «Применены временные ограничения», пока их не станет меньше трёх
  (до истечения самого раннего лишнего);
- действует серьёзное — «Аккаунт приостановлен» до его истечения.

**Ограничения** — нельзя: писать и реагировать, править сообщения, добавлять
контакты и слать заявки в друзья, создавать серверы и приглашения, менять профиль и
аватар. Можно читать, звонить, удалять своё, обслуживать ключи и устройства.
**Приостановка** — можно только читать, удалять своё и настройки безопасности.
Проверка — в экстракторе `AuthenticatedUser` (403 `account_restricted` /
`account_suspended`), по кешу в памяти, без запроса в БД.

## Наказания по пунктам Правил

Наказывается только тяжкое — п. 3.1 Правил. Оскорбления, ругань, грубость, ссоры,
троллинг, шутки (в том числе шутливые «угрозы»), надоедливые сообщения и контент 18+
между взрослыми — не нарушение (п. 1.4), мер за них нет. Jev прямо сказано: при
сомнении, всерьёз ли это, — «нарушения нет».

| Пункт | Нарушение | Обычное | Грубое |
|---|---|---|---|
| 3.1.1 | Сексуальные материалы с несовершеннолетними | Серьёзное, **бессрочно** (п. 6.2) | то же |
| 3.1.2 | Терроризм, вербовка, координация насилия | Нарушение | Серьёзное |
| 3.1.3 | Всерьёз сделанные призывы причинить физический вред конкретным людям | Нарушение | Серьёзное |
| 3.1.4 | Незаконный оборот | Нарушение | Серьёзное |
| 3.1.5 | Мошенничество, фишинг, вредоносные программы | Нарушение | Серьёзное |
| 3.1.6 | Публикация чужих персональных данных для травли | Нарушение | Серьёзное |
| 3.1.7 | Интимные материалы без согласия | Серьёзное | Серьёзное |

Мелкое нарушение (шкала тяжести < 1,5) пункта с тиром «Нарушение» — предупреждение.
Грубое — шкала тяжести ≥ 2,5. За одни и те же сообщения дважды не наказывают.
П. 3.1.8 (авторские права) и 3.2 (атаки на Сервис) по жалобе на сообщение не
рассматриваются. Все автоматические серьёзные нарушения помечены «ждёт проверки
администрацией».

Пункт убрали из `CATEGORIES` — при старте сервер снимает все действующие меры по нему
(`revoke_retired_categories`, причина «Пункт отменён…»): так 18.11.2026 сняты меры за
угрозы, преследование, спам, выдачу себя за Администрацию и 18+ в открытом месте.

## Защита OpenRouter (бесплатный тир: 20/мин, 50/сутки)

- Свои лимиты `MODERATION_MAX_PER_MINUTE` (10) и `MODERATION_MAX_PER_DAY` (40, сутки
  по UTC, счётчик в БД — переживает перезапуск); запрос считается до отправки.
- Один запрос в полёте; на 429 / 402 «in-flight budget» / 5xx — общая пауза по
  `Retry-After` или `X-RateLimit-Reset`, жалоба возвращается в очередь; после 8
  неудач — администрации. На 401/403/402 (ключ, кредиты) — пауза на час.
- До классификатора доходит не всё: квота заявителя (3 в час, 10 в сутки, не больше
  3 ждущих); жалобы на те же сообщения сливаются в один случай (один запрос на
  случай); 3 необоснованные жалобы за 7 дней — подача приостановлена до истечения
  окна; очередь ≤ 500.

## Возражения и оператор

Обвиняемый может один раз оспорить меру (`POST /api/moderation/violations/:id/appeal`).
Оператор — за `RELEASE_ADMIN_TOKEN`:

```bash
curl -H "Authorization: Bearer $RELEASE_ADMIN_TOKEN" "$API/api/admin/moderation/queue"
```

```bash
curl -X POST -H "Authorization: Bearer $RELEASE_ADMIN_TOKEN" -H 'Content-Type: application/json' -d '{"decision":"violation","category":"spam","tier":"warning"}' "$API/api/admin/moderation/reports/<id>/decide"
```

```bash
curl -X POST -H "Authorization: Bearer $RELEASE_ADMIN_TOKEN" -H 'Content-Type: application/json' -d '{"reason":"ошибка классификатора"}' "$API/api/admin/moderation/violations/<id>/revoke"
```

`…/violations/<id>/confirm` — оставить меру (снимает «ждёт проверки», отклоняет
возражение).

## Что осознанно не закрыто

- Текст личной переписки не проверяем: заявитель может приписать собеседнику
  чужие слова. До 2026-11-18 этого хватало для авто-меры жертве (вплоть до
  приостановки) — теперь нарушение из ЛС назначает только оператор. Остальная
  защита — проверка id, автора и времени по БД, пауза для тех, чьи жалобы раз за
  разом необоснованны, фрагмент на странице нарушения и возражение.
- Jev видит только текст и имена вложений; нарушение в картинке без подписи уходит
  администрации, а не решается автоматически.
