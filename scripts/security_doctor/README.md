# security-doctor

Проверки того, что **чужая страница никогда не окажется на нативном мосту**, плюс
серверные инварианты вокруг учётных данных и хранимых секретов.

```bash
./scripts/security_doctor/run.sh           # статические проверки (быстро, годится в CI)
./scripts/security_doctor/run.sh --tests   # + интеграционные тесты сервера
```

## Зачем именно так

У `crypto_doctor` и `voice_doctor` инвариант — «работает, но молча ломается».
Здесь инвариант другой:

> ни один документ, кроме собственного UI приложения, не должен оказаться во
> фрейме, которому выдан нативный мост

Мост (`window.webkit.messageHandlers` на macOS/iOS, `window.ipc` в WebView2,
`ZaliAndroidBridge` на Android) привязан к **вебвью, а не к документу** — его
получает любая страница, попавшая во фрейм. А через мост доступны токен сессии,
ключи разговоров, отправка сообщений и запись на диск. До 2026-08-22 ни в одном
из четырёх шеллов навигация не была ограничена: на Android хватало обычной
ссылки в сообщении — тап уводил вебвью на страницу атакующего вместе с мостом.

У этого слоя **нет** рантайм-тестов: нативные шеллы не покрыты ни `cargo test`,
ни JS-харнессами. Поэтому правила статические — они ловят регрессию в момент,
когда её печатают.

## Слои

### 1. `check_native_shells.mjs` — четыре шелла (21 проверка)
Origin pin в каждом: `decidePolicyFor` (macOS/iOS), `shouldOverrideUrlLoading`
(Android), `with_navigation_handler` + `with_new_window_req_handler` (WRY).
Плюс то, что политика **запрещает по умолчанию**, что внешние ссылки уходят в ОС,
и что доступ к камере/микрофону ограничен главным фреймом и известным origin
(на Android — ещё и списком ресурсов: `request.grant(request.resources)` выдавал
что попросят и кому попросят).

### 2. `check_server.mjs` — сервер (37 проверок)
JWT не принимается из query-строки (там он попадает в логи прокси, историю и
`Referer`; для WS есть одноразовый тикет на 30 секунд). Два независимых бюджета
логина — по (логин, IP) и по IP отдельно, второй считает только **неудачи**, иначе
password spray по списку логинов не тормозится ничем. Пароль не логируется даже
длиной. Таблица `conversation_keys` с открытыми ключами переписок не создаётся, а
**удаляется** при старте. Вложения отдаются `application/octet-stream` +
`attachment`, аватары определяются по сигнатуре файла, а не по присланному
Content-Type.

### 3. `check_web.mjs` — общий веб-UI (21 проверка)
`esc()` действительно экранирует все пять символов и `&` первым; нет `eval`,
`new Function`, `document.write`; текст сообщения не попадает в `innerHTML` мимо
`renderMessageText`; ключевой материал не берётся из `Math.random`.

Плюс **сканер атрибутных стоков**: каждая интерполяция `${...}` внутри значения
HTML-атрибута, не завёрнутая в `esc()`/`safeCssColor()`/`Number()`, сверяется с
`attribute_sinks.baseline.json`. Текстовая позиция сюда не входит намеренно —
там таких мест две сотни и почти все безобидны, а вот незаэкранированное
значение в `href="…"` или `style="…"` не требует даже тега: хватит кавычки.

Базлайн — это **запись о том, что место прочитали**, а не список подавлений.
Новый сток падает, пока кто-нибудь не проследит, откуда там берётся значение.
Ключ — текст выражения, а не номер строки, чтобы правки выше по файлу не
обесценивали review.

### 4. `tests/security.rs` (`--tests`) — поведение
То же самое, но против настоящего сервера на настоящем сокете: `?token=` не
пускает, тикет не переигрывается, spray по 80 логинам с одного адреса упирается
в 429, успешные входы бюджет не тратят, таблицы открытых ключей после старта нет,
чужое DM-вложение не скачивается.

## Что сюда не входит

- **Подпись релизов.** Клиент проверяет SHA-256, но сама сумма приходит из того
  же ответа `/api/version`, что и ссылка. Компрометация сервера = RCE на всех
  десктопах. Лечится подписью манифеста офлайн-ключом, вшитым в клиенты; это
  отдельная задача и требует решения о хранении ключа.
- **Аутентичность отправителя.** Сервер проставляет `sender` из JWT, и клиент ему
  верит: подписи сообщений ключом устройства нет. Скомпрометированный сервер
  может подменить автора (но не прочитать текст).
- **CSP для standalone-веб-клиента.** `msg.zalikus.org` раздаётся nginx'ом, и
  заголовки `security_headers` из этого репозитория к нему не применяются.
